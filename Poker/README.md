# Покер (техасский холдем) для проекта «Казино»

No-Limit Texas Hold'em: игрок против 1–5 ботов. Сервер — Node.js + Express + PostgreSQL,
клиент — Vite + TypeScript без фреймворков.

## Быстрый старт без базы данных (демо-режим)

Нужен только Node.js **20.19+** (или 22.12+).

```bash
npm install
npm run demo
```

Откройте <http://localhost:5173>. Балансы, столы и история хранятся в памяти сервера
и сбрасываются при его перезапуске. Игровая логика та же, что и с базой.
Сменить игрока: `http://localhost:5173/?user=2`.

> Если PowerShell пишет «выполнение сценариев отключено», используйте `npm.cmd` вместо `npm`
> (например, `npm.cmd run demo`) или один раз выполните
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

## Запуск с PostgreSQL

```bash
npm install
copy .env.example .env        # Windows (в Linux/macOS: cp .env.example .env)
```

В `.env` укажите подключение к базе в `DATABASE_URL`. Саму базу создайте заранее
(например, в pgAdmin или командой `createdb casino`). Потом:

```bash
npm run db:init   # таблицы + игра poker в games + демо-игрок demo с балансом 10 000
npm run dev       # сервер на :3000 и Vite на :5173
```

Откройте <http://localhost:5173>. Если у демо-игрока id не 1, добавьте `?user=ID` к адресу
(id напишет `db:init`).

| Команда | Что делает |
|---|---|
| `npm run demo` | демо-режим без базы: сервер с хранением в памяти + клиент |
| `npm run dev` | сервер с PostgreSQL (tsx watch) и клиент (Vite) одновременно |
| `npm test` | тесты: оценка рук, ставки, сайд-поты, боты, демо-сервис |
| `npm run typecheck` | проверка типов клиента и сервера |
| `npm run build` / `npm start` | сборка в `dist/` и запуск без Vite (Express сам отдаёт клиент) |

## Как устроено

```
db/
  01_schema.sql        таблицы казино по вашей схеме (users, games, bets, transactions, bonuses)
  02_poker.sql         игра poker в games + poker_sessions + poker_hands
  03_seed_demo.sql     демо-игрок (только для разработки)
src/shared/poker-types.ts   типы, общие для сервера и клиента
src/server/
  index.ts             Express-приложение
  auth.ts              откуда берётся id игрока (см. «Интеграция»)
  poker/
    cards.ts           колода, криптостойкое тасование
    evaluator.ts       оценка лучшей комбинации из 7 карт, названия по-русски
    engine.ts          правила: блайнды, очередь хода, рейзы, сайд-поты, вскрытие
    bot.ts             ИИ ботов
    session.ts         ход сессии: посадка, раздача, ход, выход (без хранилища)
    service.ts         хранение в PostgreSQL (транзакции, баланс, история)
    memory-service.ts  хранение в памяти — демо-режим без базы
    routes.ts          REST API
src/client/            интерфейс: лобби, стол, анимация ходов ботов
tests/                 тесты движка (node:test)
```

**Движок** (`engine.ts`) — чистые функции без БД и HTTP, поэтому он полностью покрыт тестами.
Состояние стола — обычный JSON, сервис хранит его в `poker_sessions.state`.

**Сервер — единственный источник правды.** Колода и карты ботов есть только в базе;
клиент получает «вид стола» (`buildView`), где чужие карты скрыты до вскрытия.
Карты тасуются через `crypto.randomInt`, а не `Math.random`.

**Каждый запрос — одна транзакция PostgreSQL.** Сначала блокируется строка игрока
(`SELECT … FOR UPDATE`), поэтому двойной клик или две вкладки не испортят баланс.
При ошибке всё откатывается.

## Деньги и таблицы

Покер играется «столом», как в онлайн-покер-руме:

| Событие | `bets` | `transactions` |
|---|---|---|
| Сел за стол с бай-ином 1000 | новая строка: `amount = 1000`, `payout = 0` | `bet`, `-1000` |
| Играет раздачи | — (фишки лежат на столе, в `poker_sessions.state`) | — |
| Встал с 1340 фишками | `payout = 1340`, итог сессии в `result_data` | `win`, `+1340` |
| Проиграл все фишки | `payout = 0`, сессия закрывается сама | — |

Используются только существующие типы транзакций `bet` и `win`, так что
`SUM(transactions.amount) = users.balance` всегда сходится. В `games` для покера
`min_bet`/`max_bet` — минимальный и максимальный бай-ин (200–2000), блайнды 5/10
заданы в `POKER_RULES` в `service.ts`.

Каждая раздача пишется в `poker_hands` (ваши карты, борд, банк, сколько поставили и
забрали, итог) — это экран «Последние раздачи» в лобби.

Если админ выключит игру (`games.is_active = false`), сесть за стол и начать новую
раздачу нельзя, а встать из-за стола — можно.

Если закрыть вкладку, стол не пропадёт: при следующем входе игрок вернётся к нему.

## API

Все ответы — JSON, ошибки — `{ "error": "текст" }` с кодом 400/401/403/404/409.

| Метод | Адрес | Тело | Ответ |
|---|---|---|---|
| GET | `/api/poker/config` | — | бай-ин, блайнды, баланс, список ботов |
| GET | `/api/poker/state` | — | `TableResponse` (текущий стол или `session: null`) |
| POST | `/api/poker/sit` | `{ buyIn, bots }` | `TableResponse` |
| POST | `/api/poker/action` | `{ type: "fold" \| "check" \| "call" \| "raise" \| "allin", amount? }` | `TableResponse` |
| POST | `/api/poker/next-hand` | — | `TableResponse` |
| POST | `/api/poker/leave` | — | `TableResponse` с `closed: { cashOut, profit }` |
| GET | `/api/poker/history?limit=20` | — | последние раздачи |

`amount` у `raise` — это «рейз ДО», то есть итоговая ставка игрока на улице.
В `TableResponse.frames` приходят промежуточные состояния после каждого хода бота —
клиент показывает их по очереди.

## Правила, которые реализованы

- дилер, малый и большой блайнды; один на один дилер ставит малый блайнд и ходит первым до флопа;
- минимальный рейз равен предыдущему повышению; неполный олл-ин не даёт уже ходившим повышать;
- несыгравшая ставка возвращается; основной и побочные банки; дележ банка,
  «лишняя» фишка — первому победителю слева от дилера;
- если ставить больше некому (все в олл-ине), карты докладываются до ривера автоматически;
- если игрок встаёт посреди раздачи, его карты сбрасываются, поставленное остаётся в банке.

**Боты.** До флопа оценивают руку по формуле Чена, после флопа считают шанс выиграть
(эквити) методом Монте-Карло — 300 случайных доигрываний — и сравнивают с шансами банка.
Карты соперников бот не видит. Характеры: Осторожный, Расчётливый, Агрессивный, Азартный.
Бот без фишек докупается.

## Интеграция в ваш проект

1. Скопируйте `src/server/poker`, `src/server/http-error.ts`, `src/shared/poker-types.ts`
   и выполните `db/02_poker.sql`. Файл `memory-service.ts` в рабочем проекте не нужен.
2. Подключите роутер:
   ```ts
   app.use('/api/poker', createPokerRouter(new PokerService(pool), getUserId));
   ```
3. `getUserId` в `auth.ts` уже берёт `req.user.id`, если ваша авторизация кладёт
   пользователя в `req.user`. Заглушку с заголовком `X-User-Id` включает только
   `DEV_AUTH=true` — **на настоящем сервере её надо выключить**.
4. Если у `games.code` есть `CHECK` со списком игр — добавьте туда `'poker'`.
5. Клиент: `src/client` можно встроить отдельной страницей; `api.ts` шлёт запросы
   с `credentials: 'include'`, так что cookie-сессия будет работать.

## Что можно доделать

- докупку фишек за столом (ещё одна транзакция `bet` к той же строке `bets`);
- таймер хода и автофолд;
- игру нескольких живых игроков за одним столом (WebSocket) — движок это уже поддерживает,
  места за столом не обязаны быть ботами.
